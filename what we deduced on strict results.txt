1. Meaning of "strict" in our current implementation
   In the strict runs, the empirical routing applied the paper's core routing
   constraints c1, c2, and c3 uniformly to candidate hops, including
   gateway-related hops.

2. Paper-aligned parameters we kept
   The strict runs kept the paper-style core routing parameters:
   - theta_r = pi/6
   - theta_s = pi/10
   - d_th = 4000 km
   We also changed the analytical theta_m handling so that theta_m_used_rad
   stayed fixed at pi, which is closer to the paper's case study.

3. Geometry and population were still different from the paper
   Even in the stricter runs, the experiment was not an exact reproduction of
   the paper:
   - we used real TLE-derived Starlink geometry
   - we used selected Starlink shells rather than the paper's abstract BPP tiers
   - we used public ground-station data instead of the paper's abstract gateway tier
   Therefore the strict runs were paper-aligned in constraints, but not an
   exact recreation of the original environment.

4. Current empirical strict result
   The strict empirical runs produced complete routing failure:
   - empirical interruption probability = 1.0 in all rows
   - 0 successful routes out of all tested pairs in every epoch
   This happened even after increasing the gateway count substantially.

5. Increasing gateway count alone did not fix the collapse
   Moving from the small built-in demo gateway set to the Hugging Face
   operational gateway set increased the number of gateways to 250, which is
   much closer to the paper's scale of about 300 gateways.
   Despite that, strict empirical routing still failed completely.

6. The old gateway degree caps were too restrictive, but they were not the
   main reason for total failure
   The repo originally used:
   - gs_max_sats = 4
   - gs_max_per_sat = 2
   These caps were clearly binding and were removed.
   After removal:
   - the number of edges increased substantially
   - the number of connected components dropped sharply
   - the largest connected component became much larger
   However, empirical interruption probability still stayed at 1.0.
   Therefore the degree caps were restrictive, but not the main cause of the
   complete routing failure under strict mode.

7. What the graph-level diagnostics tell us
   After removing the degree caps, topology connectivity improved a lot, but
   routing still failed completely.
   This means the collapse is now more likely caused by routing-feasibility
   constraints rather than by lack of graph connectivity alone.

8. Most likely remaining cause of failure
   The strongest remaining explanation is that strict enforcement of the
   paper's routing constraints on gateway-related hops is too harsh for the
   current TLE-derived gateway/satellite geometry.
   In other words, the graph can exist, but the strict hop-selection rules
   still prevent successful routes.

9. Important distinction from the paper
   The paper does not appear to define our repo-specific gateway-access
   engineering limits such as:
   - max satellites per gateway
   - max gateways per satellite
   - gateway elevation threshold
   - separate gateway-satellite range threshold
   These are implementation choices in the repo, not direct paper parameters.
   So failure in the strict run is not automatically a proof that the paper is
   wrong; it may also reflect incompatibility between the paper's abstract
   routing assumptions and the repo's concrete access-layer construction.

10. Current interpretation of the strict results
    The strict-paper mode is valuable as a diagnostic result.
    It suggests that the paper's routing constraints do not transfer directly
    to our current TLE-based gateway model, even after:
    - increasing gateway count toward the paper's scale
    - removing the strongest gateway degree caps
    Therefore, poor transfer under strict mode is itself a meaningful finding.

11. What the strict results do and do not mean
    The strict results do mean:
    - direct transfer from the paper to this current real-geometry setup is
      problematic
    - some assumptions in the paper-style routing model may break in a more
      concrete environment
    The strict results do not yet mean:
    - the paper is mathematically wrong
    - real satellite routing is impossible
    - the analytical model has no value

12. What this means for the FYP objective
    These strict results are still aligned with the FYP objective.
    The project goal is not to force the paper to succeed under all
    conditions. The goal is to implement the paper's idea in a more realistic
    TLE-derived setting and study how well it transfers.
    A failure to transfer cleanly is therefore a valid result, not a waste of
    effort.
